# BD-JB / Poops su PS4 12.52: esecuzione di ELF con elfldr

**Profilo osservato:** console PS4 firmware 12.52, GoldHEN 2.4b18.7, console `192.168.1.5`; computer Windows/WSL; jailbreak BD-JB via disco Blu-ray. I due `hello_world.elf` inviati al GoldHEN BinLoader 9090 hanno prodotto solo la notifica `Payload received`.

## Decisioni confermate e non confermate

- **Confermato dalla documentazione BD-JB:** su FW 12.50/12.52 si usa **Poops**, non Lapse. ISO disponibili in versioni diverse (`Poops.iso`, `HenLoader LP`, fork). Il semplice termine «BD-JB» non identifica la versione del disco o il protocollo del suo listener.
- **Confermato dalla documentazione GoldHEN:** la porta **9090** e' un BinLoader sperimentale per payload `.bin`; la **3232** e' Klog. Il toast non e' un ACK di avvio.
- **Confermato dal sorgente elfldr v0.7:** `make` produce **`elfldr.elf`** e **`elfldr.bin`**. Il secondo incorpora il primo in un bootstrap flat x86-64, costruito da `bootstrap-bin.c`; al suo avvio il bootstrap ELF crea un server ELF sulla **9021**. Il sorgente contiene il firmware `0x12520000` fra quelli gestiti dal bootstrap.
- **NON ancora provato su questa console:** compatibilita' pratica tra **`elfldr.bin` → GoldHEN 9090** e l'effettiva apertura di **9021**. La presenza di un case `0x12520000` non garantisce che le patch/offset siano corretti per ogni build.
- **NON assumere che 9020 sia disponibile:** il `bin_loader.lua` del progetto `remote_lua_loader` e' un'altra implementazione. Alcuni BD-JB fork documentano 9020 ma non e' intercambiabile senza averne verificato formato e lifecycle. In particolare l'implementazione `GoldHEN/henloader_lp` contiene un `BinLoader.java` per un payload incorporato, non prova che ci sia un server TCP generico attivo sulla 9020.

## Percorso consigliato (GoldHEN gia' avviato via BD-JB)

Questa procedura **non modifica il disco Blu-ray** e **non sovrascrive `payload.bin` sulla USB**. Prepara un loader separato e usa la porta 9090 di GoldHEN come bootstrap di primo stadio.

### 1. Preparazione locale in WSL, nessun invio alla console

```bash
cd /mnt/c/Users/gabri/Desktop/projects/fwSpoofer || exit 1
bash scripts/build.sh
bash scripts/setup_elfldr.sh
bash scripts/stage_elfldr_bin.sh
bash scripts/compare_sample.sh
python3 -m unittest discover -s tests -v
```

`stage_elfldr_bin.sh` copia `~/ps4-payload-elfldr/elfldr.bin` in `dist/elfldr.bin`, **non** il file `.elf` con nome cambiato. Nello stesso percorso viene creato `dist/elfldr.bin.sha256`. **Il PowerShell ora richiede e verifica questo checksum; la CLI ricontrolla i byte prima del trasferimento.**

**Attenzione alla provenienza:** lo SHA-256 creato da `stage_elfldr_bin.sh` conferma solo che il file non sia cambiato DOPO lo staging; non dimostra che il codice sia affidabile. La procedura PowerShell accetta direttamente l'invio della release ufficiale v0.7 con SHA pinned. Se il BIN e' stato compilato localmente con un checksum diverso, rifiuta l'invio senza anche `-AllowCustomLoader` (scelta esplicita dopo aver verificato il sorgente).

In PowerShell, dalla directory del progetto, verifica in modalità DRY RUN:

```powershell
Get-Item .\dist\elfldr.bin
python -m host.ps4_sender.cli --host 192.168.1.5 --loader goldhen --file dist/elfldr.bin
```

### 2. Prima di un singolo test reale

1. La PS4 deve essere stabile, BD-JB/Poops e GoldHEN gia' caricati, GoldHEN BinLoader abilitato (9090).
2. Abilita Klog e salva la diagnostica (3232) da un terminale separato. Conserva la traccia per distinguere errori di bootstrap da eventi indipendenti.
3. **Non inviare piu' `.elf` direttamente sulla 9090** e non eseguire alcun probe della **9020**.
4. Il bootstrap di `elfldr` applica patch a livello kernel e opera su altri processi. Il rischio di crash e perdita di dati non e' nullo. Non procedere se il sistema e' instabile o se ci sono dati non salvati.

PowerShell, SOLO quando decidi di effettuare una prova:

```powershell
.\scripts\bdjb_send_elfldr.ps1 -Send -AcceptRisk
```

L'impostazione normale dello script e' un DRY RUN: `-Send` senza `-AcceptRisk` viene rifiutato.

Se `elfldr.bin` deriva dalla tua compilazione locale e NON corrisponde allo SHA-256 fissato della release v0.7, lo script blocca l'invio finche' non aggiungi **anche** `-AllowCustomLoader` (e solo dopo aver verificato la provenienza dei sorgenti). Esempio: `./scripts/bdjb_send_elfldr.ps1 -Send -AcceptRisk -AllowCustomLoader`. Preferisci il BIN ufficiale con SHA-256 noto, ottenibile offline tramite `python scripts/fetch_official_elfldr.py --download` quando sei al PC con Internet. Questo controllo non prova comunque la compatibilita' PS4.


### 3. Verifica dell'avvio di elfldr

Dopo l'invio, su PowerShell:

```powershell
python -m host.ps4_sender.diagnostics --host 192.168.1.5 --port 9021 --require-open
```

Se la porta risulta **CLOSED**, interrompi. Non inviare alla cieca un secondo bootstrap. Acquisisci i log Klog 3232 e il comportamento della console.

Se 9021 e' **OPEN**, invia un solo ELF ufficiale:

```powershell
python -m host.ps4_sender.cli --host 192.168.1.5 --loader elfldr --file dist/hello_world_official.elf --check-elf --send
```

E' necessario **osservare il comportamento atteso** del sample ufficiale. TCP completato da solo non certifica l'esecuzione. Solo dopo un successo ripeti con `dist/hello_world.elf`, quindi `dist/firmware_info.elf`.

## Tabella sintomi

| Sintomo | Controllo | Azione |
| --- | --- | --- |
| `Payload received` su 9090 con `.elf` | Tipo errato per il BinLoader | Non ritentare `.elf`; usare bootstrap `.bin` compilato |
| `dist/elfldr.bin` mancante | `make` in `~/ps4-payload-elfldr` | `bash scripts/setup_elfldr.sh`, poi stage |
| 9090 rifiuta connessione | GoldHEN BinLoader disabilitato/PS4 IP cambiato | Verificare configurazione sullo schermo, non scansionare porte a caso |
| 9021 CLOSED dopo invio `.bin` | Bootstrap non avviato, incompatibile o crashato | Fermarsi e analizzare Klog; non presume supporto 12.52 |
| 9021 OPEN ma sample senza risultato | Linking SPRX / init del runtime / notifica nascosta | Klog + confronto ELF e versione SDK |
| Crash o blocco console | Possibile incompatibilita' del bootstrap o del sistema | Interrompere e riavviare pulito, conservare Klog |
